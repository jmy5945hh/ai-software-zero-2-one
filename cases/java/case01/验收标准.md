# 需求层面验收
1、退货字段：支持sql 和新增sql
｜原因名称 │ 退货原因的文字描述 │ 例如"商品破损"、"七天无理由退货"     │
｜排序     │ 展示顺序的权重     │ 数值越大，展示越靠前                 │
｜状态     │ 是否启用           │ 启用：前端可见可选；不启用：前端隐藏 │
｜添加时间 │ 该条记录的创建时间 │ 系统自动生成，无需人工填写           │

2、功能清单
支持以下接口；
a) 新增退货原因
    运营人员填写原因名称、排序号、启用状态，提交后系统自动记录当前时间为添加时间，保存至数据库。
b) 修改退货原因
    运营人员对已有的退货原因进行编辑，可修改原因名称、排序号、启用状态。
c) 批量删除退货原因
    运营人员勾选多条退货原因，点击"删除"按钮进行批量删除。删除后前端将不再展示这些原因选项。
d) 分页查询退货原因
    以列表形式展示所有退货原因，支持分页浏览。列表默认按排序号从高到低排列。
e) 查看退货原因详情
    查看某条退货原因的完整信息。
f) 批量启用/停用
    运营人员勾选多条退货原因，统一设置为启用或停用状态。停用的原因在前端退货下拉列表中不可见。

3、业务规则
     1. 排序规则： 列表按排序号（sort）降序展示，排序号越大越靠前。排序号相同的按添加时间倒序。
     2. 状态过滤： 状态为"不启用"（0）的退货原因，前端用户退货时不可见；状态为"启用"（1）的可见。
     3. 状态校验： 批量设置状态时，仅接受 0（不启用）和 1（启用）两个值，传入其他值操作失败。
  4. 时间自动填充： 新增退货原因时，添加时间由系统自动填充为当前服务器时间，不可人工指定。
