## 文档说明

本文档从业务视角提取系统中的关键数据实体，描述其属性和关系，为数据库设计和 API 设计提供业务基础。

**实体定义**:
- 实体名称：业务对象的名称
- 描述：实体的业务含义和用途
- 关键属性：实体的核心属性列表
- 关联关系：与其他实体的关系
- 数据生命周期：数据的创建、修改、删除规则

---

## 1. 用户与权限实体

### 1.1 用户 (User)

**业务描述**: 系统的使用者，分行内部员工

**关键属性**:

| 属性名 | 数据类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| user_id | 字符串 | 是 | 用户唯一标识，主键 |
| username | 字符串 | 是 | 登录账号 |
| password | 字符串 | 是 | 登录密码（加密存储） |
| name | 字符串 | 是 | 用户姓名 |
| role | 枚举 | 是 | 用户角色（客户经理/运营人员/审批人员/分行管理者） |
| department | 字符串 | 否 | 所属部门 |
| status | 枚举 | 是 | 用户状态（在职/离职/禁用） |
| create_time | 日期时间 | 是 | 创建时间 |
| update_time | 日期时间 | 是 | 最后修改时间 |

**关联关系**:
- 一对多：一个用户可创建多条拜访记录（作为创建人）
- 一对多：一个用户可作为参与人员出现在多条拜访记录中
- 一对多：一个用户可提交多条礼品申请（作为申请人）
- 一对多：一个用户可作为领用人出现在多条礼品申请中
- 一对多：一个用户可审批多条礼品申请（作为审批人）

**数据生命周期**:
- 创建：由系统管理员创建
- 修改：管理员可修改用户信息（除 ID 外）
- 删除：不支持物理删除，通过状态字段标记为"离职"或"禁用"

**待确认事项**:
- 是否需要支持用户头像、联系方式等扩展信息
- 是否需要支持用户组织架构（如部门树）

---

### 1.2 角色 (Role)

**业务描述**: 用户的角色类型，决定用户的权限范围

**关键属性**:

| 属性名 | 数据类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| role_code | 字符串 | 是 | 角色代码（CUSTOMER_MANAGER/OPERATIONS/ APPROVER/MANAGER） |
| role_name | 字符串 | 是 | 角色名称（客户经理/运营人员/审批人员/分行管理者） |
| description | 字符串 | 否 | 角色描述 |

**可选值**:
1. 客户经理 (CUSTOMER_MANAGER)
2. 运营人员 (OPERATIONS)
3. 审批人员 (APPROVER)
4. 分行管理者 (MANAGER)

**关联关系**:
- 一对多：一个角色可分配给多个用户

**数据生命周期**:
- 创建：系统初始化时预定义 4 种角色
- 修改：角色名称和描述可修改，角色代码不可修改
- 删除：不支持删除系统预定义角色

## 2. 首页内容实体

### 2.1 轮播图 (Carousel)

**业务描述**: 首页顶部展示的图片轮播内容

**关键属性**:

| 属性名 | 数据类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| carousel_id | 字符串 | 是 | 轮播图唯一标识，主键 |
| title | 字符串 | 是 | 轮播图标题 |
| description | 字符串 | 否 | 轮播图描述 |
| image_url | 字符串 | 是 | 图片 URL |
| link_url | 字符串 | 否 | 点击跳转链接（可选） |
| sort_order | 整数 | 是 | 排序序号（数字越小越靠前） |
| status | 枚举 | 是 | 状态（启用/禁用） |
| create_by | 字符串 | 是 | 创建人（用户 ID） |
| create_time | 日期时间 | 是 | 创建时间 |
| update_time | 日期时间 | 是 | 最后修改时间 |

**关联关系**:
- 多对一：属于一个创建人（用户）

**数据生命周期**:
- 创建：运营人员创建
- 修改：运营人员可修改所有字段
- 删除：运营人员可删除（物理删除或软删除）

---

### 2.2 新闻 (News)

**业务描述**: 首页展示的新闻公告内容

**关键属性**:

| 属性名 | 数据类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| news_id | 字符串 | 是 | 新闻唯一标识，主键 |
| title | 字符串 | 是 | 新闻标题 |
| summary | 字符串 | 是 | 新闻摘要 |
| content | 文本 | 是 | 新闻正文内容 |
| publish_time | 日期时间 | 是 | 发布时间 |
| status | 枚举 | 是 | 状态（草稿/已发布/已撤回） |
| create_by | 字符串 | 是 | 创建人（用户 ID） |
| create_time | 日期时间 | 是 | 创建时间 |
| update_time | 日期时间 | 是 | 最后修改时间 |

**关联关系**:
- 多对一：属于一个创建人（用户）

**数据生命周期**:
- 创建：运营人员创建（初始状态为"草稿"）
- 修改：运营人员可修改草稿和已发布的新闻
- 删除：运营人员可删除（物理删除或软删除）

**待确认事项**:
- 是否需要支持新闻附件（如图片、PDF）
- 是否需要支持新闻分类（如公告/活动/通知）

## 3. 客户拜访管理实体

### 3.1 客户拜访记录 (CustomerVisit)

**业务描述**: 客户经理记录的客户拜访和营销活动

**关键属性**:

| 属性名 | 数据类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| visit_id | 字符串 | 是 | 拜访记录唯一标识，主键 |
| customer_id | 字符串 | 是 | 客户 ID |
| company_name | 字符串 | 是 | 企业名称 |
| planned_date | 日期 | 是 | 计划拜访日期 |
| actual_date | 日期 | 是 | 实际拜访日期 |
| visit_method | 枚举 | 是 | 拜访方式（待确认可选值） |
| interested_products | 数组 | 否 | 意向理财产品列表（多选） |
| participants | 数组 | 否 | 参与人员列表（多选，用户 ID 列表） |
| status | 枚举 | 是 | 拜访状态（待确认可选值） |
| notes | 文本 | 否 | 备注信息 |
| create_by | 字符串 | 是 | 创建人（用户 ID） |
| create_time | 日期时间 | 是 | 创建时间 |
| update_time | 日期时间 | 是 | 最后修改时间 |

**关联关系**:
- 多对一：属于一个创建人（用户）
- 多对多：关联多个参与人员（用户）
- 一对多：可关联多条礼品申请（通过"关联客户拜访记录ID"）

**数据生命周期**:
- 创建：客户经理创建
- 修改：仅创建人可修改
- 删除：不支持物理删除（根据 BR-009）

**待确认事项**:
- "拜访方式"的可选值（现场/电话/视频/邮件等）
- "意向理财产品"的数据来源和格式
- "状态"的可选值和流转规则

## 4. 营销礼品管理实体

### 4.1 礼品基础信息 (Gift)

**业务描述**: 礼品的基础信息，包括名称、分类、单价等

**关键属性**:

| 属性名 | 数据类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| gift_id | 字符串 | 是 | 礼品唯一标识，主键 |
| gift_name | 字符串 | 是 | 礼品名称 |
| gift_category | 字符串 | 是 | 礼品分类（待确认分类维度） |
| unit_price | 金额 | 是 | 礼品单价（元） |
| stock_quantity | 整数 | 是 | 库存数量 |
| description | 字符串 | 否 | 礼品描述 |
| status | 枚举 | 是 | 状态（启用/禁用） |
| create_time | 日期时间 | 是 | 创建时间 |
| update_time | 日期时间 | 是 | 最后修改时间 |

**关联关系**:
- 一对多：一个礼品可出现在多条礼品申请中

**数据生命周期**:
- 创建：运营人员或系统管理员创建
- 修改：运营人员或系统管理员可修改
- 删除：若礼品已被使用，不支持删除；否则可删除

**待确认事项**:
- 是否需要礼品管理模块（PRD 未明确）
- 礼品分类的维度（如"实物"/"服务"，或"电子产品"/"日用品"）
- 库存管理是否需要纳入本次范围

---

### 4.2 礼品领用申请 (GiftRequisition)

**业务描述**: 客户经理提交的礼品领用审批单据

**关键属性**:

| 属性名 | 数据类型 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| requisition_id | 字符串 | 是 | 申请单唯一标识，主键 |
| applicant | 字符串 | 是 | 申请人（用户 ID） |
| recipient | 字串 | 是 | 领用人（用户 ID） |
| gift_items | 数组 | 是 | 礼品列表（每项包含礼品 ID、数量、小计） |
| total_amount | 金额 | 是 | 总金额（自动计算） |
| planned_date | 日期 | 是 | 计划领用日期 |
| purpose_type | 枚举 | 是 | 目的类型（待确认可选值） |
| related_visit_id | 字符串 | 否 | 关联客户拜访记录 ID |
| approval_status | 枚举 | 是 | 审批状态（待审批/已通过/已驳回） |
| rejection_reason | 字符串 | 否 | 驳回原因（审批状态为"已驳回"时必填） |
| approver | 字符串 | 否 | 审批人（用户 ID） |
| approval_time | 日期时间 | 否 | 审批时间 |
| create_time | 日期时间 | 是 | 创建时间 |
| update_time | 日期时间 | 是 | 最后修改时间 |

**gift_items 数据结构**:
```json
[
  {
    "gift_id": "GIFT001",
    "gift_name": "茶叶礼盒",
    "quantity": 2,
    "unit_price": 100.00,
    "subtotal": 200.00
  }
]
```

**关联关系**:
- 多对一：属于一个申请人（用户）
- 多对一：属于一个领用人（用户）
- 多对一：关联一个审批人（用户）
- 多对多：关联多个礼品（通过 gift_items）
- 多对一：可关联一条拜访记录（通过 related_visit_id）

**数据生命周期**:
- 创建：客户经理创建（初始状态为"待审批"）
- 修改：提交后不可修改（根据 BR-012）
- 删除：不支持删除

**状态流转**:
- 待审批 → 已通过（审批人员通过）
- 待审批 → 已驳回（审批人员驳回）
- 已通过/已驳回 不可变更

**待确认事项**:
- "目的类型"的可选值（客户拜访/节日慰问/营销活动等）
- 是否需要支持多级审批

---

### 4.3 礼品台账 (GiftLedger)

**业务描述**: 所有已审批通过的礼品领用记录的统计视图

**数据来源**: 审批状态为"已通过"的礼品领用申请

**关键属性**:

| 属性名 | 数据类型 | 说明 |
| --- | --- | --- |
| requisition_id | 字符串 | 申请单 ID（主键） |
| applicant | 字符串 | 申请人 |
| recipient | 字符串 | 领用人 |
| gift_items | 数组 | 礼品列表 |
| total_amount | 金额 | 总金额 |
| planned_date | 日期 | 计划领用日期 |
| actual_date | 日期 | 实际领用日期（待确认是否需要） |
| purpose_type | 枚举 | 目的类型 |
| related_visit_id | 字符串 | 关联拜访记录 ID |
| approval_time | 日期时间 | 审批通过时间 |

**关联关系**:
- 一对一：来源于一条礼品领用申请

**数据生命周期**:
- 创建：当礼品申请审批通过后，自动进入台账
- 修改：不可修改（历史记录）
- 删除：不可删除

**待确认事项**:
- 是否需要记录"实际领用日期"和"实际领用数量"（库存扣减）
- 是否需要支持导出台账数据

## 5. 运营数据实体

### 5.1 运营指标 (OperationMetrics)

**业务描述**: 数据大屏展示的关键运营指标

**数据来源**: 从客户拜访记录和礼品申请中统计计算

**关键指标**:

| 指标名称 | 计算规则 | 数据来源 |
| --- | --- | --- |
| 客户拜访次数 | COUNT(实际拜访日期不为空) | CustomerVisit |
| 营销成功次数 | COUNT(状态=营销成功) | CustomerVisit |
| 礼品领用数量 | COUNT(审批状态=已通过) | GiftRequisition |
| 礼品支出金额 | SUM(总金额 WHERE 审批状态=已通过) | GiftRequisition |

**时间维度**: 支持按天/周/月聚合

**数据更新**: 实时或准实时更新

## 6. 系统配置实体

### 6.1 系统配置 (SystemConfig)

**业务描述**: 系统的全局配置参数

**关键属性**:

| 属性名 | 数据类型 | 说明 |
| --- | --- | --- |

## 7. 数据关系图

### 7.1 核心实体关系

```
User (用户)
  ├── 1:N → CustomerVisit (作为创建人)
  ├── N:M → CustomerVisit (作为参与人员)
  ├── 1:N → GiftRequisition (作为申请人)
  ├── 1:N → GiftRequisition (作为领用人)
  ├── 1:N → GiftRequisition (作为审批人)
  ├── 1:N → Carousel (作为创建人)
  └── 1:N → News (作为创建人)

CustomerVisit (拜访记录)
  ├── 1:N → GiftRequisition (关联拜访记录)

Gift (礼品)
  ├── 1:N → GiftRequisition (通过 gift_items)

GiftRequisition (礼品申请)
  └── 虚拟表 → GiftLedger (审批状态=已通过)
```

## 8. 数据生命周期汇总

### 8.1 数据创建规则

| 实体 | 创建者 | 创建规则 |
| --- | --- | --- |
| User | 系统管理员 | 由管理员创建或批量导入 |
| Carousel | 运营人员 | 运营人员在后台创建 |
| News | 运营人员 | 运营人员创建，初始状态为"草稿" |
| CustomerVisit | 客户经理 | 客户经理在拜访后创建 |
| GiftRequisition | 客户经理 | 客户经理提交申请时创建 |
| Gift | 运营人员/管理员 | 待确认是否需要礼品管理模块 |

### 8.2 数据修改规则

| 实体 | 修改权限 | 修改规则 |
| --- | --- | --- |
| User | 系统管理员 | 除 ID 外所有字段可修改 |
| Carousel | 运营人员 | 创建人可修改所有字段 |
| News | 运营人员 | 创建人可修改所有字段 |
| CustomerVisit | 创建人 | 仅创建人可修改 |
| GiftRequisition | 不可修改 | 提交后不可修改（BR-012） |
| Gift | 运营人员/管理员 | 待确认 |

### 8.3 数据删除规则

| 实体 | 删除权限 | 删除规则 |
| --- | --- | --- |
| User | 系统管理员 | 不支持物理删除，通过状态标记 |
| Carousel | 运营人员 | 支持物理删除或软删除 |
| News | 运营人员 | 支持物理删除或软删除 |
| CustomerVisit | 不可删除 | 不支持物理删除（BR-009） |
| GiftRequisition | 不可删除 | 不支持删除 |
| Gift | 运营人员/管理员 | 若未使用可删除 |

## 9. 待确认数据项

基于 PRD 分析，以下数据概念需要与业务方进一步确认：

1. **拜访方式**: 可选值定义（现场/电话/视频/邮件等）
2. **拜访记录状态**: 可选值定义和流转规则
3. **意向理财产品**: 数据来源和格式（是否需要理财产品主数据）
4. **目的类型**: 可选值定义（客户拜访/节日慰问/营销活动等）
5. **礼品分类**: 分类维度定义
6. **礼品管理**: 是否需要礼品管理模块（礼品基础信息维护）
7. **库存管理**: 是否需要管理礼品库存数量
8. **实际领用**: 是否需要记录实际领用日期和数量（库存扣减）
9. **新闻附件**: 是否需要支持新闻附件（图片、PDF）
10. **用户扩展信息**: 是否需要用户头像、联系方式等
