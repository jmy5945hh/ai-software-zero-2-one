## 文档说明

本文档从 PRD 中提取所有业务规则，包括权限控制、状态流转、数据校验等，按模块和规则类型分组，便于架构师和开发人员理解业务逻辑。

**编号规则**: BR-001 ~ BR-999

**规则类型**:
- **权限类**: 定义角色、权限、访问控制规则
- **流程类**: 定义业务流程、状态流转规则
- **校验类**: 定义数据校验、格式验证规则
- **数据类**: 定义数据来源、计算逻辑、展示规则

## 1. 登录与权限控制规则

### BR-001: 登录认证规则

**规则类型**: 权限类

**描述**: 用户必须通过账号密码登录才能访问系统

**规则详情**:
- 用户在登录页面输入账号和密码
- 系统验证账号密码是否匹配
- 验证成功则创建会话，跳转到首页
- 验证失败则显示错误提示，停留在登录页

**适用场景**: 用户首次访问系统或会话过期后重新登录

**例外情况**: 无

**关联 User Story**: US-001

**关联验收标准**: AC-001 ~ AC-004

**待确认事项**:
- 密码复杂度要求（长度、字符类型）
- 密码过期策略（如 90 天过期）
- 账号锁定策略（如连续 5 次失败后锁定）
- 是否支持"记住我"功能

---

### BR-002: 会话管理规则

**规则类型**: 权限类

**描述**: 未登录用户无法访问任何业务页面

**规则详情**:
- 用户未登录时访问业务页面，系统自动跳转到登录页
- 登录后用户可访问与其角色匹配的功能
- 会话过期后自动跳转到登录页

**适用场景**: 所有页面访问

**例外情况**: 登录页面、静态资源（如图片、CSS）

**关联 User Story**: US-001

**关联验收标准**: AC-004

**待确认事项**:
- 会话超时时间（建议 30 分钟）
- 是否支持单点登录（SSO）
- 是否支持并发登录控制

---

### BR-003: 角色权限分配规则

**规则类型**: 权限类

**描述**: 系统定义 4 种角色，每种角色拥有不同的权限

**规则详情**:

| 角色 | 权限范围 |
| --- | --- |
| 客户经理 | 登记拜访记录、提交礼品申请、查看个人数据 |
| 运营人员 | 维护首页内容、查看运营数据、查看礼品台账 |
| 审批人员 | 审批礼品申请、查看审批历史 |
| 分行管理者 | 查看运营数据大屏、查看所有统计数据 |

**适用场景**: 所有功能模块的访问控制

**例外情况**: 无

**关联 User Story**: 全部

**关联验收标准**: AC-007, AC-010, AC-014, AC-025, AC-031

**待确认事项**:
- 一个用户是否可拥有多个角色
- 是否需要支持角色继承

---

### BR-004: 首页内容权限规则

**规则类型**: 权限类

**描述**: 只有运营人员可维护首页内容，其他角色仅可查看

**规则详情**:
- 运营人员：可新增、编辑、删除轮播图和新闻
- 其他角色：仅可查看轮播图和新闻，不可编辑

**适用场景**: 首页轮播图和新闻管理

**例外情况**: 无

**关联 User Story**: US-002, US-003

**关联验收标准**: AC-008 ~ AC-010

---

### BR-005: 功能入口动态展示规则

**规则类型**: 权限类

**描述**: 首页功能入口根据用户角色动态展示

**规则详情**:
- 系统根据用户角色查询可访问的功能模块
- 首页仅展示用户有权限访问的功能入口
- 无权限的功能入口不显示

**适用场景**: 首页功能入口展示

**例外情况**: 无

**关联 User Story**: US-002

**关联验收标准**: AC-007

---

## 2. 客户拜访管理规则

### BR-006: 拜访记录创建规则

**规则类型**: 流程类

**描述**: 客户经理可创建拜访记录，系统自动记录创建人

**规则详情**:
- 客户经理填写拜访记录表单
- 系统自动将创建人字段设置为当前登录用户
- 创建人字段不可手动修改
- 保存成功后记录状态为"新建"

**适用场景**: 客户经理新增拜访记录

**例外情况**: 无

**关联 User Story**: US-101

**关联验收标准**: AC-011, AC-012

---

### BR-007: 拜访记录数据所有权规则

**规则类型**: 权限类

**描述**: 客户经理只能查看自己创建或参与的拜访记录

**规则详情**:
- 客户经理可查看：本人创建的记录 OR 本人作为参与人员的记录
- 运营人员可查看：所有拜访记录
- 分行管理者可查看：所有拜访记录

**适用场景**: 拜访记录列表查询、详情查看

**例外情况**: 无

**关联 User Story**: US-102, US-103

**关联验收标准**: AC-014

**待确认事项**:
- 审批人员是否可查看拜访记录
- 是否需要支持跨部门协作查看

---

### BR-008: 拜访记录编辑规则

**规则类型**: 流程类

**描述**: 客户经理可编辑自己创建的拜访记录

**规则详情**:
- 只有记录的创建人可编辑该记录
- 参与人员不可编辑记录
- 编辑后更新"修改时间"和"修改人"字段

**适用场景**: 客户经理修改拜访记录

**例外情况**: 无

**关联 User Story**: US-102

**关联验收标准**: AC-015

---

### BR-009: 拜访记录删除规则

**规则类型**: 流程类

**描述**: 系统不支持物理删除拜访记录

**规则详情**:
- 拜访记录列表不提供删除按钮
- 后端 API 不提供删除接口
- 如需删除记录，可通过添加"已删除"状态标记

**适用场景**: 拜访记录管理

**例外情况**: 无

**关联 User Story**: US-102

**关联验收标准**: AC-016

**待确认事项**:
- 是否需要支持软删除（逻辑删除）
- 删除后的记录是否可在后台恢复

---

### BR-010: 拜访记录查询规则

**规则类型**: 流程类

**描述**: 支持多条件组合查询拜访记录

**规则详情**:
- 支持按时间区间查询（计划拜访日期、实际拜访日期）
- 支持按营销状态筛选
- 支持按客户 ID 精确查询
- 支持按参与人员筛选
- 多个条件之间为 AND 关系

**适用场景**: 拜访记录查询页面

**例外情况**: 无

**关联 User Story**: US-103

**关联验收标准**: AC-017 ~ AC-021

**待确认事项**:
- 是否需要支持模糊搜索（如企业名称模糊匹配）
- 是否需要保存查询条件

## 3. 营销礼品审批管理规则

### BR-011: 礼品申请提交流程

**规则类型**: 流程类

**描述**: 客户经理提交礼品申请后，申请状态变为"待审批"

**规则详情**:
- 客户经理填写礼品申请表单
- 申请人字段默认为当前登录用户，不可修改
- 提交后申请状态自动设置为"待审批"
- 提交后申请人不可修改申请内容

**适用场景**: 客户经理提交礼品申请

**例外情况**: 无

**关联 User Story**: US-201

**关联验收标准**: AC-022 ~ AC-024

---

### BR-012: 礼品申请不可修改规则

**规则类型**: 流程类

**描述**: 礼品申请提交后，申请人不可修改申请内容

**规则详情**:
- 状态为"待审批"、"已通过"、"已驳回"的申请均不可修改
- 如需修改，需撤回申请或联系审批人员驳回

**适用场景**: 客户经理查看个人礼品申请

**例外情况**: 待确认是否需要支持"撤回"功能

**关联 User Story**: US-201, US-202

**关联验收标准**: AC-024

**待确认事项**:
- 是否需要支持申请人主动撤回申请
- 撤回后的申请是否可重新提交

---

### BR-013: 礼品申请审批流程

**规则类型**: 流程类

**描述**: 审批人员可对待审批的礼品申请进行审批

**规则详情**:
- 审批人员可查看所有"待审批"状态的申请
- 审批操作：
  - 选择"通过"：申请状态变为"已通过"，不可变更
  - 选择"驳回"：必须填写驳回原因，申请状态变为"已驳回"，不可变更
- 审批完成后状态不可变更

**适用场景**: 审批人员审批礼品申请

**例外情况**: 无

**关联 User Story**: US-203

**关联验收标准**: AC-027 ~ AC-030

**待确认事项**:
- 是否需要支持多级审批（如部门负责人审批 + 分行行长审批）
- 是否需要支持审批转交（如审批人员请假，转交给其他审批人）

---

### BR-014: 礼品申请驳回规则

**规则类型**: 流程类

**描述**: 审批人员驳回礼品申请时，必须填写驳回原因

**规则详情**:
- 选择"驳回"操作时，系统显示"驳回原因"输入框
- 驳回原因为必填字段
- 未填写原因时，提交按钮禁用或提示必填

**适用场景**: 审批人员驳回礼品申请

**例外情况**: 无

**关联 User Story**: US-203

**关联验收标准**: AC-029

---

### BR-015: 礼品台账数据来源规则

**规则类型**: 数据类

**描述**: 礼品台账展示所有已审批通过的礼品申请

**规则详情**:
- 台账数据来源：所有审批状态为"已通过"的礼品申请
- 台账可按礼品类型、时间区间统计
- 运营人员和管理者可查看台账

**适用场景**: 运营人员或管理者查看礼品台账

**例外情况**: 无

**关联 User Story**: US-204

**关联验收标准**: AC-031, AC-032

**待确认事项**:
- 是否需要支持导出台账数据（如导出 Excel）
- 是否需要支持按申请人统计

## 4. 运营数据大屏规则

### BR-016: 运营指标计算规则

**规则类型**: 数据类

**描述**: 数据大屏展示的关键指标来源于系统内部业务数据

**规则详情**:

| 指标 | 计算规则 |
| --- | --- |
| 客户拜访次数 | 统计拜访记录表中"实际拜访日期"不为空的记录总数 |
| 营销成功次数 | 统计拜访记录表中"状态"为"营销成功"的记录总数 |
| 礼品领用数量 | 统计礼品申请表中状态为"已通过"的记录总数 |

**适用场景**: 运营数据大屏指标展示

**例外情况**: 无

**关联 User Story**: US-301

**关联验收标准**: AC-033, AC-037

**待确认事项**:
- "营销成功"状态的准确定义（如何判断营销成功）
- 是否需要支持自定义时间区间统计

---

### BR-017: 图表数据展示规则

**规则类型**: 数据类

**描述**: 数据大屏通过不同图表类型展示运营数据

**规则详情**:
- 折线图：展示客户拜访次数趋势（新增、总量），X 轴为时间，Y 轴为次数
- 条形图：展示每月礼品支出，X 轴为月份，Y 轴为金额
- 饼图：展示礼品分类支出占比，显示各分类的百分比和金额

**适用场景**: 运营数据大屏图表展示

**例外情况**: 无

**关联 User Story**: US-301

**关联验收标准**: AC-034 ~ AC-036

**待确认事项**:
- 图表数据更新频率（实时、每小时、每天）
- 是否需要支持图表数据下钻

---

### BR-018: 时间维度切换规则

**规则类型**: 流程类

**描述**: 用户可切换时间维度查看不同粒度的数据

**规则详情**:
- 支持的时间维度：天、周、月
- 切换时间维度后，所有图表自动更新数据
- 图表 X 轴标签根据时间维度变化

**适用场景**: 管理者或运营人员切换统计维度

**例外情况**: 无

**关联 User Story**: US-302

**关联验收标准**: AC-038, AC-039

**待确认事项**:
- 默认时间维度是什么（建议"月"）
- 是否需要支持自定义时间区间

## 5. 数据校验规则

### BR-019: 拜访记录必填字段校验

**规则类型**: 校验类

**描述**: 拜访记录表单的必填字段在提交前必须填写

**规则详情**:

| 字段 | 是否必填 | 数据类型 | 校验规则 |
| --- | --- | --- | --- |
| 客户ID | 是 | 字符串 | 非空 |
| 企业名称 | 是 | 字符串 | 非空 |
| 计划拜访日期 | 是 | 日期 | 有效日期格式 |
| 实际拜访日期 | 是 | 日期 | 有效日期格式 |
| 拜访方式 | 是 | 枚举 | 非空，值在可选列表内 |
| 意向理财产品 | 否 | 数组 | 多选，值在可选列表内 |
| 参与人员 | 否 | 数组 | 多选，值在可选列表内，默认包含当前用户 |
| 状态 | 是 | 枚举 | 非空，值在可选列表内 |

**适用场景**: 客户经理新增或编辑拜访记录

**例外情况**: 无

**关联 User Story**: US-101

**关联验收标准**: AC-013

**待确认事项**:
- 各枚举字段的可选值定义（如"拜访方式"、"状态"）
- 日期字段的格式要求（YYYY-MM-DD）

---

### BR-020: 礼品申请必填字段校验

**规则类型**: 校验类

**描述**: 礼品申请表单的必填字段在提交前必须填写

**规则详情**:

| 字段 | 是否必填 | 数据类型 | 校验规则 |
| --- | --- | --- | --- |
| 申请人 | 是 | 字符串 | 默认当前用户，不可修改 |
| 领用人 | 是 | 枚举 | 非空，值在可选列表内 |
| 礼品列表 | 是 | 数组 | 至少包含一个礼品 |
| 计划领用日期 | 是 | 日期 | 有效日期格式 |
| 目的类型 | 是 | 枚举 | 非空，值在可选列表内 |
| 关联客户拜访记录ID | 否 | 字符串 | 可选 |

**适用场景**: 客户经理提交礼品申请

**例外情况**: 无

**关联 User Story**: US-201

**关联验收标准**: AC-022

**待确认事项**:
- "目的类型"的可选值定义（如"客户拜访"、"节日慰问"、"营销活动"）
- 礼品列表中每个礼品的数据结构（礼品ID、数量、单价）

---

### BR-021: 日期逻辑校验

**规则类型**: 校验类

**描述**: 日期字段需符合业务逻辑

**规则详情**:
- 计划拜访日期 <= 实际拜访日期（或实际拜访日期可为空，表示未拜访）
- 计划领用日期 >= 当前日期（不能申请过去日期领用）

**适用场景**: 拜访记录新增/编辑、礼品申请提交

**例外情况**: 无

**关联 User Story**: US-101, US-201

**关联验收标准**: AC-013, AC-022

---

## 6. AI 问答助理规则

**规则类型**: 流程类

**描述**: AI 助理侧边栏接入大模型，提供通用对话能力

**规则详情**:
- AI 助理以侧边栏形式展示
- 用户输入问题后，系统调用大模型 API 获取回答
- 支持多轮对话，保留上下文

**适用场景**: 系统用户咨询系统使用问题

**例外情况**: 无

**关联 User Story**: US-401

**关联验收标准**: AC-040, AC-041

**待确认事项**:
- AI 知识库的范围（系统使用手册、业务规则、常见问题等）

- 是否需要支持对话历史记录
- 是否需要支持反馈机制（如"有用"/"无用"按钮）

**适用场景**: 所有涉及数据统计和展示的功能

## 8. 待确认业务规则汇总

基于 PRD 分析，以下业务规则需要与业务方进一步确认：

1. **登录认证**:
   - 密码复杂度要求和过期策略
   - 账号锁定策略
   - 会话超时时间

2. **权限管理**:
   - 一个用户是否可拥有多个角色
   - 是否需要支持角色继承
