## 文档说明

本目录包含招财银行北京分行运营门户系统的完整需求分析文档，基于 PRD v1.0 和项目范围定义文档，由高级业务分析师产出。

所有文档采用结构化格式，便于下游团队（UX 设计师、架构师、技术负责人、开发人员、测试人员）直接使用。

## 文档清单

### 1. user-stories.md - 用户故事清单

**文档说明**: 将 PRD 中的所有功能需求转化为结构化的用户故事清单

**主要内容**:
- 按模块分组的用户故事（登录与首页、客户拜访、礼品审批、数据大屏、AI 助理）
- 每个用户故事包含：编号、标题、角色、目标、收益、验收标准、优先级
- 优先级汇总（P0/P1/P2）
- 待确认需求列表

**使用对象**:
- 产品经理：确认需求范围和优先级
- UX 设计师：基于用户故事设计交互流程
- 技术负责人：基于优先级规划迭代计划
- 测试人员：基于用户故事编写测试用例

**关键统计**:
- 用户故事总数：12 个
- P0（核心）：5 个
- P1（重要）：5 个
- P2（辅助）：2 个

---

### 2. acceptance-criteria.md - 验收标准清单

**文档说明**: 从 PRD 中提取所有验收标准，提供明确的验证方法

**主要内容**:
- 按用户故事分组的验收标准
- 每个验收标准包含：编号、描述、验证方法、预期结果、可自动化程度
- 自动化测试建议（P0/P1/P2）
- 测试类型标注（功能测试、权限测试、UI 测试等）

**使用对象**:
- 测试人员：基于验收标准编写测试用例
- 开发人员：基于验收标准进行开发和自测
- 自动化测试工程师：基于可自动化标注选择自动化测试范围

**关键统计**:
- 验收标准总数：41 个
- 高度可自动化（✅）：35 个
- 部分可自动化（⚠️）：5 个
- 不可自动化（❌）：1 个

### 3. business-rules.md - 业务规则清单

**使用对象**:
- 架构师：基于业务规则设计系统架构和数据模型
- 技术负责人：基于业务规则进行技术选型和设计
- 开发人员：基于业务规则实现业务逻辑
- 测试人员：基于业务规则设计测试场景

**关键统计**:
- 业务规则总数：24 个
- 权限类：6 个
- 流程类：8 个
- 校验类：3 个
- 数据类：7 个

## 待确认事项汇总

基于 PRD 分析，以下事项需要与业务方进一步确认：

### 高优先级待确认项（影响核心功能）

1. **登录认证**:
   - 密码复杂度要求和过期策略
   - 账号锁定策略
   - 会话超时时间

2. **拜访记录**:
   - "拜访方式"的可选值定义
   - "状态"的可选值定义及流转规则
   - "营销成功"的准确定义

3. **礼品申请**:
   - 是否需要支持多级审批
   - "目的类型"的可选值定义

### 中优先级待确认项（影响用户体验）

4. **礼品管理**:
   - 礼品基础信息如何维护
   - 礼品分类的定义
   - 是否需要库存管理

5. **数据展示**:
   - 图表数据更新频率
   - 是否需要支持数据导出功能

6. **新闻详情**:
   - 是否需要支持新闻附件

### 低优先级待确认项（优化项）

7. **AI 问答**:
   - 知识库的范围和来源
   - 响应时效要求
   - 是否需要支持对话历史和反馈机制

8. **用户管理**:
   - 一个用户是否可拥有多个角色
   - 是否需要支持用户组织架构
