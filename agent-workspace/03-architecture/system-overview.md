# 系统概览

## 1. 系统简介

招财银行北京分行运营门户系统是一套专为分行内部设计的低风险运营支撑系统，旨在提供统一的运营入口，支撑日常运营登记、审批及数据查看。系统整合了客户拜访管理、营销礼品审批、运营数据统计等核心功能，并引入AI问答能力，提升系统使用便捷性和信息获取效率。

## 2. 系统目标

- 为分行员工提供统一、便捷的运营入口
- 支撑客户拜访与营销活动的规范化记录
- 提供清晰可追溯的营销礼品审批与台账管理
- 为管理人员提供直观的运营数据展示
- 引入AI问答能力，降低系统使用和信息获取成本

## 3. 系统范围

### 3.1 功能范围

| 功能模块 | 核心功能 |
|---------|---------|
| 登录与首页 | 账号密码登录、首页信息展示、内容维护 |
| 客户拜访管理 | 拜访记录登记、个人拜访记录管理、拜访记录查询 |
| 营销礼品管理 | 礼品领用申请、礼品审批、礼品台账 |
| 运营数据大屏 | 关键指标展示、数据趋势分析、多维度统计 |
| AI问答助理 | 系统使用咨询、通用问答能力 |

### 3.2 非功能范围

- 系统仅供分行内部使用，不对外开放
- 不涉及复杂的外部系统集成
- 数据来源主要为本系统内部数据
- 支持分行内部多用户同时访问

## 4. 用户角色

| 角色 | 核心职责 |
|------|---------|
| 客户经理 | 客户拜访记录登记与管理、礼品领用申请 |
| 运营人员 | 首页内容维护、运营数据查看、礼品台账管理 |
| 审批人员 | 营销礼品申请审批 |
| 分行管理者 | 运营数据大屏查看、多维度统计分析 |

## 5. 系统架构分层

系统采用分层架构设计，确保各层职责清晰、耦合度低，便于系统维护和扩展：

- **表现层**：提供用户界面，包括Web前端应用和AI助手交互界面
- **应用层**：包含业务逻辑处理、权限控制、流程管理等核心功能
- **数据层**：负责数据存储、查询和管理，包括关系型数据库和可能的缓存机制
- **集成层**：处理与外部系统的集成，如分行内部用户体系、大模型服务等

## 6. 核心业务流程

### 6.1 客户拜访管理流程

1. 客户经理新增客户拜访记录
2. 系统自动记录创建人信息
3. 客户经理可编辑本人创建的拜访记录
4. 客户经理和运营人员可按条件查询拜访记录

### 6.2 礼品领用审批流程

1. 客户经理提交礼品领用申请
2. 系统自动将申请状态设置为"待审批"
3. 审批人员查看待审批列表
4. 审批人员对申请进行审批（通过/驳回）
5. 系统更新申请状态并记录审批信息
6. 申请人可查看审批结果
7. 运营人员和管理者可查看礼品台账

### 6.3 运营数据统计流程

1. 系统从数据库中提取运营数据
2. 根据选定的时间维度（天/周/月）进行数据聚合
3. 通过可视化图表展示关键指标和趋势
4. 支持不同角色按权限查看对应数据

## 7. 系统边界

- **内部边界**：系统内部各功能模块之间的交互通过API或服务调用实现
- **外部边界**：
  - 与分行内部用户体系集成，实现账号密码登录
  - 与大模型服务集成，提供AI问答能力
  - 部署在分行内部网络环境中，不直接暴露给外部网络

## 8. 关键技术栈

- **前端技术**：React/Vue.js + Ant Design/Element UI + ECharts
- **后端技术**：Spring Boot/Node.js + MySQL/PostgreSQL
- **AI集成**：大模型API集成
- **部署环境**：分行内部服务器集群

## 9. 系统演进路线

- **v1.0**：核心功能实现，包括客户拜访管理、礼品审批、运营数据大屏
- **v2.0**：AI问答能力增强，支持更多系统使用场景
- **v3.0**：数据统计维度扩展，支持更多业务分析需求
- **v4.0**：移动端适配，支持移动设备访问

## 10. 总结

招财银行北京分行运营门户系统是一套功能完整、架构清晰的内部运营支撑系统，通过整合核心业务功能和引入AI能力，为分行员工提供了高效、便捷的运营工具。系统采用分层架构设计，确保了良好的可维护性和扩展性，能够适应未来业务发展的需求。
