# 招财银行北京分行运营门户 - 系统架构概述

## 1. 系统概述

招财银行北京分行运营门户系统是一个面向分行内部员工的运营支撑平台，旨在统一运营信息入口，规范客户拜访、营销活动记录，提供营销礼品审批管理，并为管理层提供运营数据可视化展示。系统引入AI问答功能，提升用户使用体验和信息获取效率。

## 2. 架构目标

### 2.1 业务目标
- 提供统一的运营信息入口，提升信息获取效率
- 规范客户拜访和营销活动记录流程
- 实现营销礼品的透明化审批和台账管理
- 为管理层提供直观的运营数据展示
- 通过AI问答降低系统使用和信息获取成本

### 2.2 技术目标
- 构建可扩展、可维护的前后端分离架构
- 实现基于角色的权限控制和安全认证
- 确保系统的高可用性和性能要求
- 支持与银行内部系统的集成
- 提供良好的用户体验和响应性能

## 3. 架构风格

采用前后端分离的微服务架构风格，前端使用React构建单页应用(SPA)，后端使用FastAPI提供RESTful API服务。整体架构遵循分层设计原则，包含表示层、业务逻辑层、数据访问层和数据存储层。

## 4. 技术栈

### 4.1 前端技术栈
- **核心框架**: React 18+
- **开发语言**: TypeScript 5.0+
- **构建工具**: Vite 5.0+
- **UI组件库**: Ant Design 5.x
- **状态管理**: Zustand
- **HTTP请求**: Axios
- **路由**: React Router v6
- **数据可视化**: ECharts 5.x

### 4.2 后端技术栈
- **核心框架**: FastAPI 0.110+
- **开发语言**: Python 3.10+
- **Web服务器**: Uvicorn
- **数据校验**: Pydantic v2
- **ORM**: SQLAlchemy 2.x
- **权限认证**: JWT
- **异步任务**: BackgroundTasks

### 4.3 数据存储
- **数据库**: MySQL 8.0+
- **字符集**: utf8mb4

### 4.4 AI集成
- **LLM服务**: 集成外部大语言模型服务
- **API协议**: OpenAI兼容协议

## 5. 系统边界

### 5.1 系统范围
- 内部运营门户功能
- 用户认证与权限管理
- 客户拜访记录管理
- 营销礼品审批管理
- 运营数据可视化
- AI问答助理功能

### 5.2 外部依赖
- 银行内部统一身份认证系统
- 银行核心系统（客户信息获取）
- 银行内部消息通知系统
- 银行内部AI服务平台

## 6. 部署架构

系统采用单体部署架构，前后端分离部署。前端构建为静态资源部署在Web服务器，后端API服务部署在应用服务器，数据库独立部署。系统仅供分行内部使用，通过内网访问。

## 7. 安全考虑

- 采用JWT进行身份认证和授权
- 敏感数据传输使用HTTPS协议
- 用户密码加密存储
- 系统操作日志记录
- 遵循银行数据安全和隐私保护要求
