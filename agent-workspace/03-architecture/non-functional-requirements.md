## 文档说明

本文档定义"招财银行北京分行运营门户系统"的非功能性需求，包括性能要求、可扩展性、可维护性、可观测性、兼容性和容错与灾备。

---

## 1. 性能要求

### 1.1 响应时间要求

| 操作类型 | 目标响应时间 | 最大可接受时间 |
| --- | --- | --- |
| 页面加载 | < 2 秒 | < 3 秒 |
| API 请求（简单查询） | < 500 ms | < 1 秒 |
| API 请求（复杂查询/统计） | < 2 秒 | < 5 秒 |
| AI 对话响应 | < 3 秒 | < 10 秒 |
| 数据大屏加载 | < 3 秒 | < 5 秒 |

**测量方式**:
- 使用浏览器开发者工具 Network 面板
- 使用 Apache Bench (ab) 或 JMeter 进行压力测试

### 1.2 并发用户数

**目标**:
- 支持 100 个并发用户
- 支持 500 QPS (Queries Per Second)

**测试方法**:
```bash
# 使用 Apache Bench
ab -n 10000 -c 100 http://localhost:8000/api/v1/visits
```

### 1.3 数据库性能

| 指标 | 目标值 |
| --- | --- |
| 查询响应时间 | < 100 ms |
| 数据库连接池 | 5-20 个连接 |
| 慢查询阈值 | > 2 秒 |

**优化措施**:
- 合理创建索引
- 使用分页查询
- 避免全表扫描
- 使用连接池

## 2. 可扩展性

### 2.1 水平扩展能力

**前端**:
- 静态资源可部署到 CDN
- 无状态设计，支持负载均衡

**后端**:
- 无状态 API 设计
- 可启动多个 Uvicorn Worker
- 支持水平扩展（通过 Nginx 负载均衡）

**数据库**:
- 读写分离（可选）
- 主从复制（可选）

### 2.2 垂直扩展能力

**服务器配置建议**:
- CPU: 4 核
- 内存: 8 GB
- 硬盘: 100 GB SSD

### 2.3 模块化设计

系统采用模块化设计，支持独立扩展：
- 认证模块
- 拜访管理模块
- 礼品管理模块
- 内容管理模块
- 数据大屏模块
- AI 助理模块

## 3. 可维护性

### 3.1 代码质量

**前端**:
- TypeScript 类型检查通过
- ESLint 检查通过
- 组件单一职责原则
- 代码注释完善

**后端**:
- Python 类型提示（typing）
- Pylint 或 Flake8 检查通过
- 函数单一职责原则
- 代码注释完善

### 3.2 文档完整性

| 文档类型 | 说明 |
| --- | --- |
| API 文档 | 自动生成 OpenAPI/Swagger 文档 |
| 架构文档 | 本文档，描述系统架构 |
| 开发文档 | 环境搭建、开发规范 |
| 部署文档 | 部署流程、配置说明 |
| 用户手册 | 系统使用说明（可选） |

### 3.3 测试覆盖率

| 测试类型 | 覆盖率要求 | 说明 |
| --- | --- | --- |
| 单元测试 | 核心业务逻辑 > 80% | Service 层业务逻辑 |
| 集成测试 | 关键流程 > 60% | API 接口测试 |
| E2E 测试 | 核心用户故事 > 50% | 完整用户流程 |

**测试工具**:
- 前端: Vitest + Testing Library + Playwright
- 后端: pytest + pytest-asyncio + httpx

### 3.4 代码可读性

**规范**:
- 遵循 PEP 8 (Python) 和 ESLint (TypeScript)
- 使用有意义的变量和函数名
- 避免魔法数字，使用常量
- 复杂逻辑添加注释

## 4. 可观测性

### 4.1 日志记录

**日志级别**:
- DEBUG: 调试信息（开发环境）
- INFO: 一般信息（生产环境）
- WARNING: 警告信息
- ERROR: 错误信息
- CRITICAL: 严重错误

**日志内容**:
```json
{
  "timestamp": "2026-01-08T10:00:00",
  "level": "INFO",
  "logger": "visit_service",
  "message": "Visit created successfully",
  "user_id": "USER001",
  "visit_id": "VISIT001",
  "ip": "192.168.1.100"
}
```

**日志存储**:
- 开发环境: 控制台输出
- 生产环境: 文件存储 + 日志轮转
- 日志保留时间: 30 天

### 4.2 监控指标（可选）

**系统指标**:
- CPU 使用率
- 内存使用率
- 磁盘使用率
- 网络流量

**应用指标**:
- API 请求数
- API 响应时间
- 错误率
- 数据库连接数

**业务指标**:
- 活跃用户数
- 拜访记录创建数
- 礼品申请提交数
- AI 对话次数

**监控工具**（可选）:
- Prometheus + Grafana
- ELK (Elasticsearch + Logstash + Kibana)

### 4.3 告警机制（可选）

**告警规则**:
- API 错误率 > 5%
- API 响应时间 > 5 秒
- 数据库连接失败
- 服务器 CPU > 80%
- 服务器内存 > 80%

**告警方式**（可选）:
- 邮件告警
- 钉钉/企业微信告警
- 短信告警（严重故障）

## 6. 容错与灾备

### 6.1 故障处理

**数据库连接失败**:
- 使用连接池自动重连
- 返回友好错误提示

**外部 API 调用失败**（如 LLM API）:
- 超时时间: 60 秒
- 重试次数: 3 次
- 返回友好错误提示

**前端请求失败**:
- 显示全局错误提示
- 提供"重试"按钮

### 6.2 数据备份

**备份策略**:
- 全量备份: 每周一次
- 增量备份: 每天一次
- 日志备份: 实时备份 binlog

**备份保留**:
- 全量备份保留 1 个月
- 增量备份保留 1 周

**备份存储**:
- 本地存储
- 异地存储（可选）

### 6.3 灾难恢复

**RPO (Recovery Point Objective)**:
- 最多丢失 1 天数据

**RTO (Recovery Time Objective)**:
- 4 小时内恢复服务

**恢复流程**:
1. 评估故障影响
2. 准备恢复环境
3. 恢复数据库备份
4. 验证数据完整性
5. 启动应用服务
6. 验证功能正常

### 6.4 降级策略

**AI 助理降级**:
- 如果 LLM API 不可用，显示"AI 服务暂时不可用"提示
- 不影响其他功能使用

**数据大屏降级**:
- 如果统计数据查询超时，显示"数据加载失败"提示
- 提供"重试"按钮

## 11. 性能测试计划

### 11.1 测试工具

- **Apache Bench (ab)**: 简单压测
- **JMeter**: 复杂场景压测
- **Locust**: Python 脚本压测

### 11.2 测试场景

| 场景 | 并发用户 | 请求总数 | 目标 |
| --- | --- | --- | --- |
| 登录 | 50 | 1000 | 错误率 < 1%，响应时间 < 500 ms |
| 查询拜访记录 | 100 | 10000 | 错误率 < 1%，响应时间 < 1 秒 |
| 新增拜访记录 | 50 | 1000 | 错误率 < 1%，响应时间 < 500 ms |
| 数据大屏统计 | 20 | 500 | 错误率 < 1%，响应时间 < 3 秒 |

### 11.3 测试命令示例

```bash
# 登录接口压测
ab -n 1000 -c 50 -p login.json -T application/json http://localhost:8000/api/v1/auth/login

# 查询拜访记录压测
ab -n 10000 -c 100 -H "Authorization: Bearer <token>" http://localhost:8000/api/v1/visits
```
