# 项目范围定义

**文档创建时间**：2026-01-07
**Orchestrator 负责人**：MainAgent

---

## 1. 本次验证目标

### 1.1 核心目标
建设一套**分行内部运营门户系统**，实现：
- 客户拜访与营销活动的规范化记录
- 营销礼品领用的审批流程与台账管理
- 运营数据的可视化展示
- AI 智能问答辅助

### 1.2 验证范围（MVP）
- 基于 PRD v1.0 实现全部功能模块
- 前后端分离架构，React + FastAPI
- MySQL 数据持久化
- 支持 4 类角色的 RBAC 权限控制

---

## 2. 明确边界

### 2.1 本次包含的功能
1. **登录与首页模块**
   - 账号密码登录
   - 首页轮播图、新闻展示
   - 运营人员维护首页内容

2. **客户拜访与理财营销登记管理**
   - 登记客户拜访记录
   - 管理个人拜访记录（CRUD）
   - 查询拜访记录（多条件筛选）

3. **营销礼品领用审批管理**
   - 客户经理提交礼品申请
   - 审批人员审批（通过/驳回）
   - 礼品台账查看与统计

4. **运营数据大屏**
   - 关键运营指标展示
   - 多维度图表（折线图、条形图、饼图）
   - 时间维度切换（天/周/月）

5. **AI 问答助理（侧边栏）**
   - 接入大模型提供通用 chat 问答能力
   - 侧边栏形式展示

### 2.2 本次不包含的功能
- 集成外部系统（如核心银行系统、CRM）
- 移动端适配（仅 PC 端）
- 复杂的工作流引擎（固定审批流即可）
- 数据导出功能
- 系统日志审计功能
- 高级权限控制（字段级、按钮级）

---

## 3. 关键约束

### 3.1 技术约束
- 前端必须使用：React 18+ + TypeScript + Vite + Ant Design 5.x
- 后端必须使用：FastAPI + Python 3.10+ + SQLAlchemy 2.x
- 数据库：MySQL 8.0+
- 状态管理：Zustand
- 数据可视化：ECharts

### 3.2 环境约束
- 数据库已配置：host=127.0.0.1, port=3306, db=zero_one
- JWT 已配置密钥与算法
- LLM API 已配置（火山引擎）

### 3.3 质量约束
- 所有接口必须有 OpenAPI/Swagger 文档
- 前端代码需通过 TypeScript 类型检查
- 核心业务逻辑需有单元测试覆盖
- 关键用户故事需有 E2E 测试验证

## 6. 风险与假设

### 6.1 风险
- AI 问答能力依赖外部 API，稳定性待验证
- 数据库 Schema 可能需要多轮调整
- 前后端接口契约可能变更

### 6.2 假设
- 用户已在局域网环境，网络稳定
- 并发用户量 < 100，无需性能优化
- AI 问答为辅助功能，容忍一定延迟
