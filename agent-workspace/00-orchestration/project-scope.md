# 项目范围定义

## 1. 本次验证目标

本次项目旨在构建**招财银行北京分行运营门户系统**，作为分行内部低风险运营支撑系统，提供统一的运营入口，支撑日常运营登记、审批及数据查看。

### 1.1 核心功能范围

- ✅ 登录与首页模块
- ✅ 客户拜访与理财营销登记管理
- ✅ 营销礼品领用审批管理
- ✅ 运营数据大屏
- ✅ AI 问答助理（侧边栏）

### 1.2 技术栈范围

严格遵循 user_docs/技术栈.md 中定义的技术选型：

- **前端**：React 18+、TypeScript 5.0+、Vite 5.0+、Ant Design 5.x 等
- **后端**：FastAPI 0.110+、Python 3.10+、SQLAlchemy 2.x 等
- **数据库**：MySQL 8.0+

### 1.3 环境配置

严格使用 user_docs/环境&配置.md 中提供的配置信息：

- 数据库连接参数
- JWT 配置
- LLM API 配置

## 2. 不做什么

- ❌ 不支持外部系统集成
- ❌ 不实现字段级、按钮级权限控制
- ❌ 不提供移动端适配
- ❌ 不包含复杂的工作流引擎
- ❌ 不实现数据导出功能（如 Excel 导出）
- ❌ 不实现系统日志审计功能

## 3. 交付边界

- 本次交付为 MVP 版本，覆盖核心业务流程
- 所有功能均在分行内部网络环境下运行
- 数据仅来源于本系统内部，不涉及外部数据导入
- AI 问答助理仅提供系统使用相关咨询，不涉及业务数据查询

## 4. 验证标准

- 功能完整性：覆盖 PRD 中所有 User Story
- 技术可行性：所有组件可正常运行，无编译错误
- 性能要求：页面操作响应及时，无明显卡顿
- 安全性：实现基于 JWT 的身份认证，未登录用户无法访问业务页面

## 5. 项目约束

- 项目周期：精益 MVP 迭代，每阶段产出可校验的里程碑
- 开发资源：仅通过 Subagent 进行开发，不涉及外部人力
- 部署环境：本地开发环境，不涉及生产部署
- 测试范围：核心功能的单元测试和集成测试，不包含性能测试和安全测试
