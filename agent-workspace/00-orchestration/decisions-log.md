## 决策 #001：采用精益 MVP 迭代策略

**日期**：2026-01-07
**决策者**：Orchestrator

### 决策内容
不追求一次性生成功能完整、性能完美的软件，而是采用精益 MVP 迭代思路，分阶段交付：
- Phase 1：基础框架与登录
- Phase 2：核心业务功能
- Phase 3：数据展示与 AI

### 决策原因
1. 降低复杂度，提高可交付性
2. 每个 Phase 都可独立验证
3. 便于及时调整方向

### 影响范围
- 整个项目开发流程
- Subagent 任务拆解粒度
- Review 节点设置

### 状态
`active`

## 决策 #002：使用文件系统作为交付物存储

**日期**：2026-01-07
**决策者**：Orchestrator

### 决策内容
所有 Subagent 的输出必须落盘为文件，存储在 `agent-workspace/` 目录下，而不是仅在对话上下文中传递。

### 决策原因
1. 节省对话上下文空间
2. 提高 AI 生成准确率（基于文件生成而非记忆）
3. 便于人类随时查看和介入
4. 建立可追溯的项目文档体系

### 影响范围
- 所有 Subagent 的任务描述
- 交付物的位置约定
- Orchestrator 的验收方式

### 状态
`active`

## 决策 #004：禁止 Subagent 直接对话

**日期**：2026-01-07
**决策者**：Orchestrator
