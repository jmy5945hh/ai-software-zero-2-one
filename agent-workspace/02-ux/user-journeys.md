## 文档说明

本文档为"招财银行北京分行运营门户系统"的用户旅程地图，描述四种角色（客户经理、运营人员、审批人员、分行管理者）在关键业务场景下的操作流程、触点和情绪体验。

**旅程地图包含要素**:
- 角色：执行任务的系统用户类型
- 场景：具体的业务场景
- 目标：用户希望达成的目标
- 操作步骤：用户完成目标的操作序列
- 触点：用户与系统交互的关键界面
- 情绪曲线：用户在各阶段的情绪变化
- 痛点：用户遇到的阻碍或困难

## 1. 客户经理用户旅程

### 1.1 日常拜访登记流程

**角色**: 客户经理

**场景**: 客户经理完成客户拜访后，需要记录拜访情况和营销进展

**目标**: 快速、准确地记录客户拜访信息，为后续礼品申请提供依据

**操作步骤**:

```
步骤 1: 进入拜访记录页面
  - 操作：点击主导航"拜访管理" → "拜访记录"
  - 界面：拜访记录列表页
  - 情绪: 😐 平静
  - 痛点: 无

步骤 2: 新增拜访记录
  - 操作：点击"新增"按钮
  - 界面：拜访记录编辑表单
  - 情绪: 😊 期待
  - 痛点: 无

步骤 3: 填写拜访信息
  - 操作：填写客户ID、企业名称、拜访日期、拜访方式、参与人员等
  - 界面：表单填写
  - 情绪: 😐 平静
  - 痛点: 客户ID需要手动输入，不支持搜索
    参与人员多选操作不够直观

步骤 4: 提交拜访记录
  - 操作：填写完成后点击"提交"
  - 界面：表单提交，返回列表页
  - 情绪: 😊 满意
  - 痛点: 无

步骤 5: 确认记录保存
  - 操作：查看列表中新增的记录
  - 界面：拜访记录列表
  - 情绪: 😊 满意
  - 痛点: 无
```

**触点**:
- 主导航菜单
- 拜访记录列表页
- 拜访记录编辑表单
- 成功提示消息

**情绪曲线**:
```
平静 → 期待 → 平静 → 满意 → 满意
😐    😊    😐    😊    😊
```

**优化建议**:
1. 客户ID字段支持搜索联想
2. 参与人员多选提供更直观的交互方式
3. 提交后自动跳转到详情页，方便继续编辑

### 1.2 礼品申请与审批流程

**角色**: 客户经理

**场景**: 客户经理需要为客户拜访申请礼品资源

**目标**: 提交礼品申请，快速获取审批结果

**操作步骤**:

```
步骤 1: 进入礼品申请页面
  - 操作：点击主导航"礼品管理" → "礼品申请"
  - 界面：礼品申请列表页
  - 情绪: 😐 平静
  - 痛点: 无

步骤 2: 新增礼品申请
  - 操作：点击"新增"按钮
  - 界面：礼品申请表单
  - 情绪: 😊 期待
  - 痛点: 无

步骤 3: 填写申请信息
  - 操作：选择领用人、添加礼品、选择目的类型、关联拜访记录
  - 界面：表单填写
  - 情绪: 😐 平静
  - 痛点: 礼品列表中无法看到库存数量
    关联拜访记录需要手动输入拜访ID

步骤 4: 提交申请
  - 操作：确认信息无误后点击"提交"
  - 界面：表单提交，返回列表页
  - 情绪: 😊 期待
  - 痛点: 无

步骤 5: 查看审批状态
  - 操作：在列表中查看申请状态
  - 界面：礼品申请列表
  - 情绪: 😊 期待
  - 痛点: 列表中看不到审批进度（如排队中、审批中）
    无法查看审批人是谁

步骤 6: 收到审批结果通知（待确认）
  - 操作：收到系统通知（暂未设计）
  - 界面：通知中心或邮件
  - 情绪: 😊 满意 / 😞 失望
  - 痛点: 系统暂未设计主动通知功能
```

**触点**:
- 主导航菜单
- 礼品申请列表页
- 礼品申请表单
- 状态标签（待审批/已通过/已驳回）

**情绪曲线**:
```
平静 → 期待 → 平静 → 期待 → 期待 → 满意/失望
😐    😊    😐    😊    😊    😊/😞
```

**优化建议**:
1. 礼品列表显示库存数量，避免申请超量
2. 关联拜访记录支持从个人拜访记录中选择
3. 列表显示审批人和审批进度
4. 增加系统通知功能，及时告知审批结果

## 5. 跨角色业务流程：从拜访到礼品申请

### 5.1 完整业务流程

**场景**: 客户经理完成客户拜访 → 提交礼品申请 → 审批人员审批 → 形成礼品台账

**角色**: 客户经理 → 审批人员 → 运营人员/管理者

**操作步骤**:

```
阶段 1: 客户经理 - 登记拜访记录
  - 操作：创建拜访记录，填写拜访信息
  - 界面：拜访记录表单
  - 状态流转：拜访记录创建成功

阶段 2: 客户经理 - 提交礼品申请
  - 操作：创建礼品申请，关联拜访记录
  - 界面：礼品申请表单
  - 状态流转：申请状态 = "待审批"

阶段 3: 审批人员 - 审批申请
  - 操作：查看申请详情，选择通过或驳回
  - 界面：申请详情页
  - 状态流转：
    - 通过：申请状态 = "已通过" → 进入礼品台账
    - 驳回：申请状态 = "已驳回"

阶段 4: 运营人员/管理者 - 查看台账
  - 操作：查看礼品台账，统计礼品使用情况
  - 界面：礼品台账列表
  - 数据流转：已通过的申请自动进入台账

阶段 5: 管理者 - 查看数据大屏
  - 操作：查看运营指标和图表
  - 界面：运营数据大屏
  - 数据聚合：从拜访记录和礼品台账中统计数据
```

**触点**:
- 拜访记录表单
- 礼品申请表单
- 礼品审批列表
- 礼品台账
- 运营数据大屏

**关键交互点**:
1. 礼品申请关联拜访记录：需要在申请表单中选择或输入拜访记录ID
2. 审批决策：审批人员通过或驳回申请
3. 数据自动聚合：已通过的申请自动进入台账，数据大屏实时更新

**流程痛点**:
1. 礼品申请关联拜访记录时，需要手动输入或选择拜访ID（UX待优化）
2. 审批人员无法直接查看关联的拜访记录详情
3. 客户经理无法收到审批结果的主动通知（系统未设计通知功能）
4. 数据大屏未说明数据更新频率

**角色**: 所有系统用户

**场景**: 用户在使用系统过程中遇到问题，需要咨询 AI 助理

**目标**: 快速获取系统使用帮助

**操作步骤**:

```
步骤 1: 打开 AI 助理
  - 操作：点击右下角的 AI 助理图标
  - 界面：AI 助理侧边栏展开
  - 情绪: 😊 期待
  - 痛点: 无

步骤 2: 输入问题
  - 操作：在输入框中输入问题
  - 界面：对话界面
  - 情绪: 😐 平静
  - 痛点: 无快捷问题选项

步骤 3: 等待 AI 回复
  - 操作：系统调用大模型获取回答
  - 界面：显示"正在思考..."
  - 情绪: 😐 平静
  - 痛点: 无

步骤 4: 查看回复
  - 操作：AI 返回回答
  - 界面：显示 AI 回复内容
  - 情绪: 😊 满意 / 😞 失望
  - 痛点: 回答可能不准确（依赖大模型能力）
    无法判断 AI 回答是否正确

步骤 5: 继续对话或关闭
  - 操作：继续提问或点击关闭按钮
  - 界面：对话界面或收起侧边栏
  - 情绪: 😊 满意
  - 痛点: 对话历史未保存（待确认）
```

**触点**:
- AI 助理图标（右下角）
- AI 助理侧边栏
- 对话输入框
- 回复显示区域

**情绪曲线**:
```
期待 → 平静 → 平静 → 满意/失望 → 满意
😊    😐    😐    😊/😞     😊
```

**优化建议**:
1. 首次打开时显示快捷问题选项（如"如何提交礼品申请？""如何查看拜访记录？"）
2. 增加"有用"/"无用"反馈按钮，帮助优化 AI 回答
3. 支持对话历史保存
4. AI 回复中引用相关的系统文档链接
5. 显示 AI 回答的置信度或来源

## 7. 用户痛点汇总

### 7.1 客户经理痛点

1. **客户ID输入不便**: 需要手动输入客户ID，不支持搜索联想
2. **参与人员选择体验差**: 多选操作不够直观
3. **礼品库存不可见**: 申请礼品时无法查看库存数量
4. **关联拜访记录不便**: 需要手动输入拜访记录ID
5. **审批进度不透明**: 无法查看审批人和审批进度
6. **缺少通知功能**: 无法收到审批结果的主动通知

### 7.2 运营人员痛点

1. **图片上传无预览**: 轮播图上传不支持预览和裁剪
2. **编辑器功能简单**: 新闻正文编辑器功能有限（待确认）
3. **台账缺少统计**: 礼品台账未显示汇总统计
4. **筛选条件不可保存**: 无法保存常用筛选条件

### 7.3 审批人员痛点

1. **缺少优先级标识**: 无法识别高优先级或超时申请
2. **详情信息不完整**: 无法查看关联拜访记录和礼品库存
3. **驳回原因无快捷选项**: 需要手动输入驳回原因
4. **不支持批量审批**: 只能逐条审批（待确认是否需要）

### 7.4 分行管理者痛点

1. **指标缺少环比**: 无法判断指标趋势是好是坏
2. **图表交互性弱**: 无法下钻查看详情
3. **时间区间受限**: 仅支持维度切换，不支持自定义区间
4. **更新频率不明**: 不清楚数据何时更新

## 8. 待确认功能

基于用户旅程分析，以下功能需要与业务方进一步确认：

1. **系统通知功能**: 是否需要支持审批结果通知、系统公告推送等
2. **数据统计卡片**: 拜访记录列表、礼品台账列表是否需要显示汇总统计
3. **礼品库存管理**: 是否需要在申请界面显示礼品库存
4. **拜访记录关联**: 礼品申请时是否支持从拜访记录列表中选择
5. **批量审批**: 是否需要支持审批人员批量审批礼品申请
6. **数据导出**: 是否需要支持拜访记录、礼品台账导出为 Excel
7. **新闻富文本编辑**: 新闻正文是否需要支持富文本（图片、格式化等）
8. **AI 对话历史**: AI 助理是否需要保存对话历史
9. **数据大屏自定义时间区间**: 是否需要支持自定义时间区间查询
10. **指标环比**: 数据大屏指标卡片是否需要显示环比/同比数据
