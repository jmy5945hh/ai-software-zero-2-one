# 信息架构

## 1. 系统整体结构

招财银行北京分行运营门户系统采用分层架构设计，包括：

- **用户层**：不同角色的用户通过统一入口访问系统
- **导航层**：提供全局导航、角色导航和功能导航
- **功能层**：包含所有业务功能模块
- **数据层**：存储和管理系统数据

## 2. 导航设计

### 2.1 全局导航

全局导航固定在页面顶部，包含：

| 导航元素 | 功能描述 | 可见角色 |
|----------|----------|----------|
| 系统 Logo | 显示系统名称和标识 | 所有角色 |
| 首页 | 跳转至系统首页 | 所有角色 |
| 功能菜单 | 根据角色动态显示功能入口 | 所有角色 |
| 用户信息 | 显示当前登录用户信息，提供退出登录功能 | 所有角色 |
| AI 助手入口 | 打开/关闭侧边栏AI问答助理 | 所有角色 |

### 2.2 角色导航

根据用户角色不同，导航菜单动态显示不同的功能入口：

#### 客户经理角色

```
- 首页
- 客户拜访管理
  - 拜访记录列表
  - 新增拜访记录
- 礼品申请
  - 我的申请列表
  - 新增礼品申请
```

#### 审批人员角色

```
- 首页
- 礼品审批
  - 待审批列表
  - 已审批列表
```

#### 运营人员角色

```
- 首页
  - 轮播图管理
  - 新闻管理
- 客户拜访管理
  - 拜访记录查询
- 礼品管理
  - 礼品台账
- 运营数据大屏
```

#### 分行管理者角色

```
- 首页
- 运营数据大屏
```

### 2.3 页面内导航

各功能页面内部采用清晰的层级导航：

- **列表页**：顶部筛选区 + 中部操作区 + 底部分页区
- **表单页**：顶部标题 + 中部表单区 + 底部操作按钮
- **详情页**：顶部返回按钮 + 中部详情信息 + 底部相关操作
- **大屏页**：顶部维度切换 + 中部图表展示

## 4. 内容组织

### 4.1 内容优先级

1. **核心业务功能**：根据角色不同，优先展示常用功能入口
2. **关键信息展示**：首页突出显示最新公告和新闻
3. **数据可视化**：运营数据大屏优先展示关键指标
4. **辅助功能**：AI问答助理作为侧边栏辅助功能

### 4.2 内容分类

- **操作类内容**：功能按钮、表单输入、筛选条件
- **信息类内容**：新闻、公告、记录列表、详情信息
- **数据类内容**：图表、统计指标、台账
- **辅助类内容**：帮助信息、系统提示、错误信息

## 5. 搜索与筛选设计

### 5.1 搜索功能

- **全局搜索**：暂不提供全局搜索功能
- **局部搜索**：各列表页提供针对当前模块的搜索功能

### 5.2 筛选功能

| 功能模块 | 筛选条件 |
|----------|----------|
| 客户拜访记录 | 时间区间、营销状态、客户ID、参与人员 |
| 礼品申请 | 申请状态、时间区间、申请人 |
| 礼品审批 | 审批状态、时间区间 |
| 礼品台账 | 礼品类型、时间区间 |
| 运营数据大屏 | 时间维度（天/周/月） |

## 6. 权限控制

- **菜单级权限**：根据角色显示不同的功能菜单
- **页面级权限**：未授权用户无法访问特定页面
- **操作级权限**：部分操作（如编辑、删除）仅对特定角色开放

## 7. 响应式设计考虑

- 系统主要面向桌面端使用，优先保证桌面端体验
- 支持1024px以上的屏幕分辨率
- 关键功能在小屏设备上仍可正常使用
- 大屏数据可视化部分针对大屏幕进行优化
