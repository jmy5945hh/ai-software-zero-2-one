## 文档说明

本文档定义"招财银行北京分行运营门户系统"的信息架构，包括导航结构、页面层级和页面跳转关系。

**设计原则**:
- 按角色权限展示不同的导航菜单
- 扁平化层级结构，最多 3 级导航
- 符合用户心智模型的分类方式
- 保持导航的一致性和可预测性

---

## 1. 整体导航结构

### 1.1 顶部导航栏

所有登录用户共享的顶部导航栏，包含：

```
┌─────────────────────────────────────────────────────────────┐
│  Logo  |  面包屑导航  |         搜索框（可选）        | 用户菜单 │
└─────────────────────────────────────────────────────────────┘
```

**组件说明**:
- **Logo**: 点击跳转到首页
- **面包屑导航**: 显示当前页面位置，支持点击跳转
- **用户菜单**: 包含用户信息、退出登录、AI 助理入口

---

### 1.2 左侧主导航菜单

根据用户角色动态展示，采用可折叠的侧边栏设计。

**通用结构**:

```
一级菜单
  ├── 二级菜单（可选）
  │     └── 三级页面（可选）
  └── 直接跳转页面
```

## 4. 页面层级与跳转关系

### 4.1 登录流程

```
登录页 (/login)
  └─ 登录成功 → 首页 (/home)
```

---

### 4.2 拜访管理流程

```
拜访记录列表 (/visit-records)
  ├─ 新增按钮 → 拜访记录新增 (/visit-records/new)
  │               └─ 提交 → 返回列表
  ├─ 详情按钮 → 拜访记录详情 (/visit-records/:id)
  │               ├─ 编辑按钮 → 拜访记录编辑 (/visit-records/:id/edit)
  │               │               └─ 保存 → 返回详情
  │               └─ 关闭 → 返回列表
  └─ 编辑按钮 → 拜访记录编辑 (/visit-records/:id/edit)
                  └─ 保存 → 返回列表
```

---

### 4.3 礼品申请流程（客户经理）

```
礼品申请列表 (/gift-applications)
  ├─ 新增按钮 → 礼品申请新增 (/gift-applications/new)
  │               ├─ 关联拜访记录 → 可跳转到拜访记录详情
  │               └─ 提交 → 返回列表
  ├─ 详情按钮 → 礼品申请详情 (/gift-applications/:id)
  │               └─ 关闭 → 返回列表
  └─ 状态标签 → 仅查看，不可编辑
```

---

### 4.4 礼品审批流程（审批人员）

```
礼品审批列表 (/gift-approvals)
  ├─ 审批按钮 → 礼品审批详情 (/gift-approvals/:id)
  │               ├─ 查看关联拜访记录 → 可跳转到拜访记录详情（只读）
  │               ├─ 通过 → 返回列表
  │               └─ 驳回 → 返回列表
  └─ 审批历史 → 审批历史 (/gift-approvals/history)
                    └─ 详情按钮 → 申请详情（只读）
```

---

### 4.5 礼品台账查看流程

```
礼品台账 (/gift-ledger)
  └─ 详情按钮 → 礼品申请详情（只读） (/gift-applications/:id)
                  └─ 关闭 → 返回列表
```

---

### 4.6 内容管理流程（运营人员）

```
轮播图管理 (/content/carousels)
  ├─ 新增按钮 → 轮播图新增/编辑 (/content/carousels/new)
  │               └─ 保存 → 返回列表
  ├─ 编辑按钮 → 轮播图新增/编辑 (/content/carousels/:id/edit)
  │               └─ 保存 → 返回列表
  └─ 删除按钮 → 确认删除 → 返回列表

新闻管理 (/content/news)
  ├─ 新增按钮 → 新闻新增/编辑 (/content/news/new)
  │               ├─ 保存草稿 → 返回列表
  │               └─ 发布 → 返回列表
  ├─ 编辑按钮 → 新闻新增/编辑 (/content/news/:id/edit)
  │               ├─ 保存草稿 → 返回列表
  │               └─ 发布 → 返回列表
  └─ 删除按钮 → 确认删除 → 返回列表

首页新闻详情 (/content/news/:id/detail)
  └─ 关闭 → 返回首页
```

---

### 4.7 数据大屏流程

```
数据大屏 (/dashboard)
  └─ 无子页面，所有图表在单页展示
```

---

### 4.8 个人中心流程

```
用户菜单
  ├─ 个人信息 → 个人信息页面 (/profile)
  │               └─ 保存 → 刷新页面
  └─ 修改密码 → 修改密码页面 (/change-password)
                  └─ 提交 → 退出登录，返回登录页
```

## 5. 面包屑导航设计

### 5.1 面包屑规则

面包屑导航显示当前页面的层级路径，格式为：

```
首页 > 一级菜单 > 二级菜单 > 当前页面
```

**示例**:

| 当前页面 | 面包屑导航 |
| --- | --- |
| 拜访记录列表 | 首页 > 拜访管理 > 拜访记录 |
| 拜访记录详情 | 首页 > 拜访管理 > 拜访记录 > 详情 |
| 拜访记录编辑 | 首页 > 拜访管理 > 拜访记录 > 编辑 |
| 礼品申请新增 | 首页 > 礼品管理 > 礼品申请 > 新增 |
| 礼品审批列表 | 首页 > 礼品管理 > 礼品审批 |
| 数据大屏 | 首页 > 数据大屏 |

---

### 5.2 面包屑交互

- 点击面包屑中的任意节点，跳转到对应页面
- 首页节点固定为第一项
- 面包屑最多显示 4 级（超出部分省略）

---

## 6. 侧边栏折叠与展开

### 6.1 侧边栏状态

侧边栏支持两种状态：

1. **展开状态**（默认）: 显示菜单图标 + 菜单文字
2. **折叠状态**: 仅显示菜单图标，鼠标悬停时显示菜单文字

---

### 6.2 折叠交互

- 点击折叠按钮，侧边栏在展开/折叠状态间切换
- 折叠状态下，鼠标悬停在菜单图标上，显示悬浮菜单
- 系统记住用户的侧边栏状态（localStorage）

### 7.2 无权限访问处理

当用户尝试访问无权限的页面时：

1. **直接访问 URL**: 跳转到 403 页面，提示"无权限访问"
2. **菜单项隐藏**: 无权限的菜单项不显示在主导航中

## 8. AI 助理入口

### 8.1 全局入口

AI 助理以浮动按钮形式固定在页面右下角，所有页面均可访问。

**位置**:
- 固定在右下角，距离底部 30px，距离右侧 30px
- 始终置顶，不随页面滚动

**交互**:
- 点击按钮，展开 AI 助理侧边栏
- 再次点击或点击侧边栏外部区域，收起侧边栏

---

### 8.2 侧边栏状态

AI 助理侧边栏支持两种状态：

1. **展开状态**: 显示对话界面（宽度约 400px）
2. **收起状态**: 仅显示圆形图标按钮

---

## 9. 响应式设计说明

**本系统仅支持 PC 端，无需移动端响应式设计。**

**PC 端分辨率支持**:
- 最低支持分辨率: 1366 x 768
- 推荐分辨率: 1920 x 1080

**布局适配**:
- 内容区域自适应屏幕宽度
- 数据大屏在大屏幕下显示效果更佳

## 10. 待确认事项

基于信息架构设计，以下事项需要与业务方确认：

1. **拜访统计页面**: 客户经理是否需要查看个人拜访统计数据（P2 功能）
2. **审批历史**: 审批人员是否需要查看审批历史记录
3. **礼品审批权限**: 运营人员是否也需要拥有礼品审批权限
4. **新闻详情页**: 用户点击首页新闻后，跳转到独立的详情页还是弹窗
5. **数据大屏访问权限**: 是否需要限制数据大屏的访问权限（当前仅运营人员和管理者可访问）
6. **个人中心功能**: 是否需要支持修改个人信息（如联系方式、部门等）
7. **导航菜单图标**: 是否需要为每个菜单项设计图标（当前未明确）
