## 文档目录

### 1. 用户旅程地图 (user-journeys.md)

**用途**: 描述四种角色在关键业务场景下的操作流程、触点和情绪体验

**内容**:
- 客户经理用户旅程（日常拜访登记、礼品申请与审批、查看个人数据）
- 运营人员用户旅程（维护首页内容、查看运营数据）
- 审批人员用户旅程（审批礼品申请）
- 分行管理者用户旅程（查看运营数据大屏）
- 跨角色业务流程（从拜访到礼品申请）
- AI 助理使用流程
- 用户痛点汇总

**关键产出**:
- 识别了 4 个角色共 8 个关键用户旅程
- 每个旅程包含操作步骤、触点、情绪曲线和痛点
- 汇总了 30+ 用户痛点，提供优化建议

## 设计原则

### 1. 简洁高效

- B 端系统，强调操作效率
- 减少不必要的视觉元素
- 提供快捷键和批量操作

### 2. 角色适配

- 不同角色看到不同的导航菜单
- 不同角色有不同的权限控制
- 界面根据用户角色动态展示

### 3. 流程清晰

- 关键业务流程有明确引导
- 状态流转清晰可见
- 提供面包屑导航，明确当前位置

### 4. 反馈及时

- 每个操作都有明确反馈
- Loading 状态清晰可见
- 错误提示具体明确

### 5. 一致性

- 统一的交互模式
- 统一的视觉语言
- 统一的术语表达

---

## 设计亮点

### 1. 扁平化信息架构

- 最多 3 级导航，避免深层嵌套
- 面包屑导航明确当前位置
- 支持快速跳转

### 2. 基于角色的权限设计

- 4 种角色，4 种不同的导航视图
- 页面和功能根据权限动态展示
- 数据访问权限严格控制

### 3. 完整的业务流程设计

- 从拜访记录 → 礼品申请 → 审批 → 台账
- 流程清晰，状态明确
- 支持跨页面关联

### 4. 基于 Ant Design 5.x

- 使用成熟的组件库
- 统一的视觉语言
- 易于前端实现

### 5. 可访问性考虑

- 键盘导航支持
- 屏幕阅读器支持
- 颜色对比度符合 WCAG 标准

## 待确认事项

### 高优先级（影响核心功能）

1. **拜访记录状态**: 可选值定义和流转规则
2. **礼品申请目的类型**: 可选值定义
3. **营销成功定义**: 准确定义和判断标准
4. **礼品基础信息**: 如何维护（礼品管理模块）

### 中优先级（影响用户体验）

1. **系统通知功能**: 是否需要支持审批结果通知
2. **数据统计卡片**: 拜访记录、礼品台账是否显示汇总统计
3. **礼品库存管理**: 是否需要在申请界面显示库存
4. **拜访记录关联**: 是否支持从拜访记录列表中选择

### 低优先级（优化体验）

1. **数据导出**: 是否需要支持导出 Excel
2. **批量操作**: 是否需要支持批量审批、批量删除
3. **高级筛选**: 是否需要支持保存筛选条件
4. **AI 对话历史**: 是否需要保存对话历史
