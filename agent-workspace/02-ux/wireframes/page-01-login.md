## 4. 交互行为说明

### 4.1 输入框交互

**账号输入框**:
- 获得焦点: 显示蓝色边框
- 失去焦点: 恢复默认边框
- 输入内容: 实时显示输入内容

**密码输入框**:
- 获得焦点: 显示蓝色边框
- 失去焦点: 恢复默认边框
- 输入内容: 显示掩码（●●●●）
- 显示/隐藏切换: 点击眼睛图标，切换密码显示/隐藏（可选）

---

### 4.2 表单提交

**键盘操作**:
- Tab 键: 在输入框之间切换焦点
- Enter 键: 提交表单（当焦点在登录按钮上时）

**鼠标操作**:
- 点击登录按钮: 提交表单

---

### 4.3 登录流程

**步骤 1: 用户输入账号和密码**

**步骤 2: 点击登录按钮**

**步骤 3: 表单验证**
- 验证账号是否为空
- 验证密码是否为空
- 验证失败: 在字段下方显示错误提示

**步骤 4: 提交登录请求**
- 请求: POST /api/login
- 参数: `{ username, password }`

**步骤 5: 处理登录结果**

**成功**:
- 保存 JWT Token 到 localStorage
- 跳转到首页 (/home)

**失败**:
- 在表单顶部显示错误提示
- 清空密码框
- 保持账号框内容
- 焦点回到账号框

---

### 4.4 状态变化

**初始状态**:
- 显示空表单
- 登录按钮启用

**提交中状态**:
- 登录按钮显示 loading 图标
- 登录按钮禁用
- 输入框禁用

**失败状态**:
- 显示错误提示
- 登录按钮恢复启用
- 输入框恢复启用
- 清空密码框

**成功状态**:
- 跳转到首页

---

## 5. 数据来源

**API 接口**:

```
POST /api/login

Request:
{
  "username": "string",  // 账号
  "password": "string"   // 密码
}

Response (Success):
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "string",       // JWT Token
    "user": {
      "user_id": "string",
      "name": "string",
      "role": "string"       // 客户经理/运营人员/审批人员/管理者
    }
  }
}

Response (Failure):
{
  "code": 401,
  "message": "账号或密码错误"
}
```

## 8. 可访问性

### 8.1 键盘导航

- Tab 键: 在输入框和按钮之间切换焦点
- Enter 键: 提交表单
- ESC 键: 清空表单（可选）

### 8.2 屏幕阅读器

- 表单字段添加 `aria-label` 属性
- 错误提示添加 `role="alert"` 属性

### 8.3 对比度

- 文字颜色与背景色对比度 ≥ 4.5:1
- 错误提示使用红色，对比度足够

## 9. 加载与错误状态

### 9.1 首次加载

**页面加载**:
- 显示静态页面
- 无 loading 状态

### 9.2 提交中状态

**登录按钮**:
- 显示 loading 图标（旋转动画）
- 按钮文字: "登录中..."
- 按钮禁用

### 9.3 错误状态

**网络错误**:
- 提示: "网络错误，请稍后重试"
- 显示错误图标

**账号或密码错误**:
- 提示: "账号或密码错误"
- 清空密码框
- 焦点回到账号框

**账号被禁用**:
- 提示: "您的账号已被禁用，请联系管理员"
- 显示错误图标
- 不允许重试

## 10. 待确认事项

1. **密码找回**: 是否需要提供"忘记密码"功能
2. **记住我**: 是否需要"记住我"功能（保持登录状态）
3. **账号输入**: 是否支持手机号或工号登录
4. **密码复杂度**: 后端是否校验密码复杂度（前端是否需要提示）
5. **会话超时**: 登录后多久需要重新登录（30分钟？）
6. **单点登录**: 是否需要支持单点登录（SSO）
7. **账号锁定**: 连续多少次失败后锁定账号（5次？）
