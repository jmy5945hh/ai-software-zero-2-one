## 四、核心功能特性

### 4.1 拜访管理模块

#### ✅ 数据级权限控制
- **客户经理**: 只能查看自己创建或参与的拜访记录
- **运营人员、管理者、审批人员**: 可以查看所有拜访记录
- **编辑权限**: 只有拜访记录的创建人可以编辑

#### ✅ 业务规则校验
- 实际拜访日期不能早于计划拜访日期
- 参与人员默认包含创建人
- 支持多条件筛选（时间区间、状态、客户ID、创建人）

#### ✅ 分页与排序
- 支持分页查询（可配置页大小）
- 支持多字段排序
- 排序方向可选（升序/降序）

### 4.2 礼品管理模块

#### ✅ 完整的审批流程
- **申请提交**: 客户经理可以提交礼品申请
- **审批通过**: 审批人员可以审批通过申请
- **审批驳回**: 审批人员可以驳回申请（必须填写驳回原因）
- **状态流转**: 待审批 → 已通过/已驳回（不可逆）

#### ✅ 数据级权限控制
- **客户经理**: 只能查看自己的申请
- **运营人员、管理者、审批人员**: 可以查看所有申请
- **审批权限**: 只有 APPROVER 角色可以审批
- **台账权限**: 只有运营人员和管理者可以查看台账

#### ✅ 业务规则校验
- 计划领用日期不能早于今天
- 驳回时必须填写驳回原因
- 只能审批待审批状态的申请
- 自动计算申请总金额

#### ✅ 礼品台账功能
- 只显示已审批通过的记录
- 支持按礼品分类筛选
- 支持按时间区间筛选

## 五、技术实现亮点

### 5.1 分层架构
严格遵循分层架构设计：
```
API 路由层 → Service 层 → CRUD 层 → Model 层
```

### 5.2 依赖注入
- 使用 FastAPI 的依赖注入系统
- `get_current_user` 自动获取当前登录用户
- `get_db` 自动管理数据库会话

### 5.3 类型安全
- 所有函数都有完整的类型注解
- 使用 Pydantic v2 进行数据校验
- 使用 `computed_field` 处理嵌套对象序列化

### 5.4 数据库优化
- 使用 `joinedload` 预加载关联对象，避免 N+1 查询
- 正确配置外键关系和级联规则
- 使用索引优化查询性能

### 5.5 错误处理
- 统一的 `ApiResponse` 响应格式
- 明确的 HTTP 状态码
- 详细的错误信息
- 业务异常和权限异常分离
